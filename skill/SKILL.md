# Xiaolab 模板使用说明

## 何时用

当用户要：

- 用 xiaolab 组会模板出一份新汇报
- 保持品牌骨架不变，但重做模板组织方式
- 清理模板、概览、references
- 把模板收成“极少默认页 + 可拼装组件”
- 扩展更多样式，但不希望语义页越长越多

## 先立总原则

### 1. 先按表达组织，再去取页

不要默认“把内容依次填进整套模板”。

正确顺序：

1. 先判断这次组会要表达什么
2. 再定只需几页
3. 再从组件库里取布局
4. 不够再补；多了就删

结论：

- **先有表达结构，再有模板拼接**
- **组件服务内容，不是内容迁就组件**

### 2. 默认只留极少核心页

真实组会默认只需：

- 封面
- 一页主内容
- 下一步（若有）

其余都不算默认页，只算**可拼装组件页**。

### 3. 模板正文尽量留空

HTML deck 本体不应预置：

- 示例文案
- 教学提示语
- 可见占位符文案（如 `{{主标题}}`）
- 默认四格数字
- 默认列表点位
- 默认流程箭头装饰
- 默认卡片 / 面板 / 大色块

可保留：

- 极少封面识别字段
- 空文字区
- 空图片区
- 布局骨架

结论：**空白优于伪内容。**

### 4. 原则不应上屏

这些东西应写在 skill / references，不应出现在可见页面：

- `核心页 / 参考页`
- `备注：……`
- “这页只有在……时才用”
- “前两三页够用时……”

同理，ESC 概览也应保持简洁：

- 默认只保页码、页名
- 仅当页面上真有主标题，才额外显示主标题
- 不抓 notes / 摘要 / 教学句

## 组件化方向

目标不是增加更多“某某页”，而是维护一组可拼装组件。

当前模板中的组件应理解为：

- 双列图文
- 双图对照
- 三栏带
- 四格媒体区
- 上下分栏
- 左重右轻
- 右重左轻
- 流程带
- 对照区

后续若要扩展，也应优先加：

- 更通用的布局骨架
- 更少装饰的留白样式
- 更灵活的文字 / 图片比例

而不是继续发明很多语义页名。

## 默认产物

默认产物是 **单文件 HTML deck**。

除非用户明言要 `.pptx`，否则按 HTML deck 交付。

## references 使用方式

`references/` 只留仍有长期价值的收束文档。

若某次迭代只是临时排错、局部试错、一次性坐标记录，任务收束后应主动清理；避免把 references 堆成流水账。

当前保留策略：

- 保留可复用的总原则 / 教训收束
- 删除一次性中间发现、重复结论、已被总文档吸收的碎片笔记

## 交付检查

完成前至少检查：

- 模板本体是否仍有多余说明文
- overview 是否仍泄漏备注 / notes / 摘要
- 是否误把组件做成固定内容结构
- 是否又长出默认框、默认色块、默认列表点位
- 第七页这类对照组件是否仍残默认 bullet 结构
- GitHub 远端是否已同步
